# 0007 Vitest replaces the check scripts, and the HTTP fake stays a real server

Verification used to be six standalone Node programs (`scripts/check-*.mjs`) run through `pnpm check:*`, each importing `apps/web/lib/*.ts` via `--experimental-strip-types`, asserting with `node:assert/strict` and printing `PASS`. They were a deliberate choice — a test framework was refused at the time — and they worked. This ADR records why that changed, because the change deletes a file whose own header calls it indispensable.

**What forced it: the `@/` alias.** The app's modules import each other as `@/lib/…`, a path Node cannot resolve. `scripts/alias-loader.mjs` existed solely to teach it how, and its header said so plainly: without it, *"anything importing `@/lib/…` — including the module where the deploy verdict's only judge lives — is unreachable from Node and therefore untestable."* Reachability was being bought with a bespoke module loader, and the bill kept growing: an async loader (the synchronous variant broke Node's CJS named-export detection for `react`), a `--import` preamble, and a `DEP0205` suppression flag in the package script. Vitest resolves the same aliases from `tsconfig.json` for free, so the loader, its registrar, and the flags all go.

**What it unlocked.** Reachability was never only about the alias. `judgeAction` was testable, but the loop that decides *when* it has enough evidence lived inside `app/page.tsx` — 2,187 lines of component. The old check could not call it, so it asserted on the file's source text instead: `pageSource.includes('judgeAction')`. A grep is not a test; it passes for code that is never executed. That loop is now `lib/wait-for-completion.ts`, taking its listing, deployment lookup and clock as parameters, and the failed-vs-succeeded deploy scenario of ADR-0006 runs end to end against a fake instance on a virtual clock. This is the only production change the migration made.

**Vitest over the alternatives.** `node:test` is now a real option — Node strips types natively — but it keeps the loader for the alias and needs a DOM wired by hand for `renderHook`, which the Batch Queue specs require. Jest fits ESM, Next 16 and React 19 badly enough to need a transform and a module mapper. Vitest brings TS, ESM, alias resolution, jsdom and coverage with one config file.

**The HTTP fake stays a real server.** Every spec that touches the network starts a `node:http` server on an ephemeral port and lets the real `CoolifyClient` reach it (`apps/web/test/fake-coolify.ts`). Mocking `fetch` — with MSW or a stub — would be tidier and faster, and would assert our beliefs about the client rather than exercise it: URL construction per resource type, query-string composition, the `x-coolify-url`/`x-coolify-token` header contract with the proxy, and the way a 422's `errors` map becomes a readable message. Those are exactly the seams that have broken before. The cost is a server per spec file, which measures in milliseconds.

**What did not change.** The OpenAPI file remains the source of truth for payload shape; its extractor moved to `apps/web/test/coolify-spec.ts` and still validates every clone payload, env-var request and log query against `coolify-openapi-v4.x.yaml`. Each migrated spec keeps the original's header comment verbatim — the *why* those checks exist is the part worth preserving.

Scope is `lib/` and `hooks/`. Components are deliberately uncovered: their tests would be markup-shaped and brittle, and the decisions worth pinning were pulled out of them instead. Coverage is reported but not gated — a threshold picked before knowing the baseline buys filler tests, not confidence. No CI runs the suite yet; `pnpm test` and the `test` task in `turbo.json` are the whole story.
